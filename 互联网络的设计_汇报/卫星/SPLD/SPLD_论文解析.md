## 0. 一句话总结

论文问了一个很直白的问题——**"从网络角度看，构建一个既能抗毁、性能又够用的 LSN，到底需要多少颗卫星？"**——然后把"需要多少颗星"形式化为 **SPLD 问题**（最小化卫星数 $\min\sum_i x(i)$，同时满足：任一对地面小区之间至少有 $r_{ij}$ 条**边不相交路径**、每个小区的上/下行容量需求、以及每条冗余路径的**跳数上限** $\lceil\lambda\cdot L^{sp}_{ij}\rceil$）。

SPLD 是 NP-hard（即使所有 $r=1$、只取一个时间片，也退化成 Steiner Tree）。作者的做法不是硬解，而是抓住一个非对称性：**"优化很难，但判定可行很容易"**——把时延约束转成**有向分层图**，用**最大流**在线性时间内判定"$r$ 条边不相交路径 + 容量"是否满足；然后外面套一层 **Shrink / Expand 二分调参**，每轮调完再判定一次，直到收敛。这就是 **MEGAREDUCE**。

结论：即便在 $r_{\min}=6$ 这样严苛的生存性要求下，Starlink 一期规模仍可压掉 **20.05%**、Kuiper 压掉 **21.88%** 的卫星数；并且这套"需求 → 星数"的映射是**可逆**的（$N^{sat}\leftrightarrow req$），可以直接用来指导**分期部署**和**在轨星座衰减后的结构调整**。

## 2. 系统模型（§III-A）

### 2.1 时变图

- 卫星集合 $S=\{s_1,s_2,\dots\}$；地面设施**聚合为小区** $C=\{c_1,c_2,\dots\}$（工程上按 H3 六边形分层地理索引 [40] 划分），每个小区可由点波束覆盖并建立双向链路。
- 时间**离散为时隙**，用二值量 $I^t_{ij}$ 表示 $i,j$ 在时隙 $t$ 是否**互相可见**；用 $e^t_{ij}=1$ 表示时隙 $t$ 存在**活跃通信链路**。显然必须有 $I^t_{ij}\ge e^t_{ij}$——不可见就不可能建链。
- 于是 LSN 建模为**时变图** $G^t=(V,E^t)$，其中 $V=S\cup C$，$E^t$ 包含时隙 $t$ 所有活跃的 GSL（多对多）与 ISL。**LEO 的高动态全部体现在 $E^t$ 随时间变化上。**

### 2.2 容量模型

- 每颗宽带卫星配多个高吞吐点波束，**波束共享卫星整体的上/下行能力**（受功率供给约束）[3]；假设**一个点波束服务一个地面小区**。
- 记时隙 $t$ 卫星 $i$ 与小区 $j$ 之间该波束的上/下行容量为 $\mathrm{Cap}^t_{ji}$、$\mathrm{Cap}^t_{ij}$；卫星上/下行最大容量为 $\mathrm{Cap}^{\max}_{up}$、$\mathrm{Cap}^{\max}_{down}$。
- 卫星 $i$ 的**实时**上行容量 $=\sum_{j\in C}e^t_{ji}\cdot \mathrm{Cap}^t_{ji}$；小区 $j$ 在时隙 $t$ 的**总可达**上行容量 $=\sum_{i\in S}e^t_{ji}\cdot \mathrm{Cap}^t_{ji}$（下行对称）。
- **一个被显式写进假设的关键简化**：激光 ISL 的容量远高于射频 GSL [4]，在已有空间流量调度（如 SpaceRTC [38]）下 **ISL 不会是瓶颈**，因此后续容量约束**只算 GSL，不算 ISL**。→ 见 §9.2 第 2 条。

### 2.3 通信需求

需求集合 $D=\{d_1,d_2,\dots\}$，每条 $d_k$ 用三元组 $(\mathrm{src}(d_k),\mathrm{dst}(d_k),\mathrm{size}(d_k))$ 描述：两端小区 + 流量速率。可以是视频会议流，也可以是 Web 请求/响应。

### 2.4 生存性定义：$R$-边连通（全文最关键的定义）

- $[i\to j]$ 路径 = LSN 图中的一个节点-边序列；**边不相交（edge-disjoint）**= 没有任何一条边出现在多于一条路径里。
- 需求 $d$ 关联的 $(i,j)$ 称为 **$R$-边连通**，当且仅当**在所有时隙里**，$i$ 与 $j$ 之间都至少有 $R$ 条边不相交路径。
- 需求 $(i,j)$ 的生存性要求记为 $r_{ij}$（对称：$r_{ij}=r_{ji}$），含义是"**每一个时隙**都要有至少 $r_{ij}$ 条边不相交路径"。

**为什么用边不相交路径数当抗毁指标**：这是把"故障后可恢复"翻译成图论量的最省事做法——$r_{ij}$ 条边不相交路径 ⟺ 任意**单链路故障**最多打断其中一条，剩下 $r_{ij}-1$ 条仍然通。代价是它只刻画**链路**冗余，不刻画**节点（卫星）**失效时的冗余（要刻画节点冗余得换成节点不相交路径）。→ 可攻击点之一。

注意"**所有时隙**"这个量词非常强：它把 LSN 的高动态从"性能问题"变成了"约束问题"——星座转一圈，任何时刻都不能掉到 $r_{ij}$ 条以下。这也是后面 $N_{\min}$ 要比直觉大的原因。

## 3. 基础 SPLD 形式化（§III-B）

**问题陈述**：给定一个基于 mega-constellation 的初始 LSN，以及一串生存性与性能要求，**如何优化网络结构，找到一个满足全部要求、且卫星数最少的子图？**

设二值变量 $x(i)$ 表示卫星 $i\in S$ 是否被选入子图，$T$ 为所有时隙集合。

$$\text{Objective:}\quad \min \sum_{i\in S} x(i)$$

$$\text{s.t.}\quad I^t_{ij} \ge e^t_{ij},\quad \forall i,j\in S\cup C,\ i\ne j,\ \forall t\in T \tag{1}$$
$$x(i)\cdot x(j) \ge e^t_{ij} \tag{2}$$
$$\sum_{j\in S} e^t_{ij} \le N_{ISL},\quad \forall i\in S \tag{3}$$
$$\sum_{\forall d:\,\mathrm{src}(d)=j}\mathrm{size}(d) \le \sum_{i\in S} e^t_{ji}\cdot \mathrm{Cap}^t_{ji},\quad \forall j\in C,\ \forall t\in T \tag{4}$$
$$\sum_{\forall d:\,\mathrm{dst}(d)=j}\mathrm{size}(d) \le \sum_{i\in S} e^t_{ij}\cdot \mathrm{Cap}^t_{ij},\quad \forall j\in C,\ \forall t\in T \tag{5}$$
$$\sum_{j\in C} e^t_{ji}\cdot \mathrm{Cap}^t_{ji} \le \mathrm{Cap}^{\max}_{up},\quad \forall i\in S,\ \forall t\in T \tag{6}$$
$$\sum_{j\in C} e^t_{ij}\cdot \mathrm{Cap}^t_{ij} \le \mathrm{Cap}^{\max}_{down},\quad \forall i\in S,\ \forall t\in T \tag{7}$$
$$\sum_{(i,j)\in\sigma(V')} e^t_{ij} \ge \max_{\forall p\in V-V',\ \forall q\in V'} r_{pq},\quad \forall V'\subset V,\ V'\ne\varnothing \tag{8}$$

### 3.1 约束逐条解读

| 编号 | 约束 | 作用 | 值得注意的点 |
|---|---|---|---|
| (1) | $I^t_{ij}\ge e^t_{ij}$ | 只能给**可见**的两端建链 | 把轨道力学（可见性）与网络决策解耦：$I^t$ 由星历算出，$e^t$ 是决策变量 |
| (2) | $x(i)x(j)\ge e^t_{ij}$ | 卫星没被选进子图就不能建链 | **非线性（双线性）**。做 ILP 需线性化为 $e^t_{ij}\le x(i)$、$e^t_{ij}\le x(j)$；论文未提。见 §9.2 第 9 条 |
| (3) | $\sum_j e^t_{ij}\le N_{ISL}$ | 每条卫星**同时**启用的 ISL 数不超过其激光终端数 | 本文实验取 $N_{ISL}=4$（与 Starlink/Iridium 一致） |
| (4)(5) | 小区级上/下行聚合容量 | 该小区**所有**需求的流量之和不超过该小区的上/下行可达容量 | 是**聚合**约束（不是逐需求），隐含"所有需求同时承载、不等时复用" |
| (6)(7) | 卫星级 GSL 容量上限 | 单星点波束总容量受**功率**约束 | 与 (4)(5) 合起来才完整：小区侧要够、卫星侧也不能超 |
| (8) | **割约束**：任意割 $V'$ 上活跃边数 $\ge$ 被该割分开的任意需求对的最大 $r_{pq}$ | 保证 $r_{ij}$-边连通 | 见下面的专门说明 |

### 3.2 关于约束 (8) 的正确性与代价

论文的解读是："$V'$ 是顶点集的子集，$\sigma(V')$ 是把 $V'$ 从 $V$ 中分出去的那些边；该约束保证分开 $p,q$ 的**最小割**至少为 $r_{pq}$，从而由 Menger 定理存在至少 $r_{pq}$ 条边不相交路径。"

**这个推导是对的**，值得停一下确认——因为多商品场景下"割条件"通常不充分（经典的整多商品流对偶间隙）。这里不冲突的原因是：**"$p$ 与 $q$ 之间有几条边不相交路径"是一个逐对的连通性属性，不涉及不同商品之间共享链路容量**。对任意给定对 $(p,q)$，取其最小割 $C_{pq}$，该割的右端是"被它分开的所有需求对里最大的 $r$"，必然包含 $(p,q)$ 的 $r_{pq}$，于是 $\sum_{e\in C_{pq}}e \ge r_{pq}$，即 $\lambda(p,q)\ge r_{pq}$。逐对成立即可，不需要跨对一致。所以 (8) 是**充分**的、用一族割约束紧凑地编码了所有对的要求。

**代价**：(8) 是对 **$V$ 的所有子集 $V'$** 施加约束，约束条数**指数级**。要真按 ILP 交给求解器，必须用割分离（cut separation）回路按需加割。→ 但注意：MEGAREDUCE **根本不解这个 ILP**，(8) 只在问题声明里存在，算法层面用逐需求的 max-flow 绕开了它（§6.5）。**所以这两个 ILP 是"问题的定义"，不是"被求解的对象"**——这是读本文时必须分清的一点，否则会以为 20% 的削减是 ILP 解出来的。

## 4. 带时延约束的扩展（§III-C）—— 全文最巧的一步

基础 SPLD 只保证"有 $r_{ij}$ 条边不相交路径"，但**没保证这些备份路径够短**。工程上备份路径如果绕地球半圈，故障切换后 QoE 直接崩。所以要给路径加**长度（跳数）上限**：

$$L_d = L_{ij} = \lceil \lambda\cdot L^{sp}_{ij}\rceil,\qquad \lambda\ge 1$$

其中 $L^{sp}_{ij}$ 是 $i,j$ 之间最短路径长度，$\lambda$ 是**约束因子**（借用 Gvozdiev 等 SIGCOMM'18 的低时延拓扑研究 [41] 的做法）。$\lambda=1.35$ 意即"备份路径最多比最短路径多 35% 的跳数"。

### 4.1 图变换：为什么必须"分层"

"最多 $L_d$ 跳 + $r_d$ 条边不相交"这两个约束**没法直接塞进一个最大流**——最大流是"容量约束下的单商品流"，而跳数是一个**路径级**的整型约束。标准破解法就是**时间/跳数展开成层**：

把无向图 $G^t=(V,E^t)$ 换成**有向分层图** $G^d_t=(V^d,E^d_t)$，每个需求 $d$ 一张，共 $L_d+1$ 层：

$$V^d = V^d_1\cup V^d_2\cup\dots\cup V^d_{L_d+1},\quad V^d_1=\{\mathrm{src}(d)\},\ V^d_{L_d+1}=\{\mathrm{dst}(d)\},\ V^d_l = V-\{\mathrm{src}(d)\}\ (l=2,\dots,L_d)$$

- 层内不连边；**只连相邻层**：对原图每条边 $(i,j)\in E^t$，连 $i$ 在第 $l$ 层的副本 $i^d_l$ 到 $j$ 在第 $l+1$ 层的副本 $j^d_{l+1}$，即 $(i^d_l,j^d_{l+1})$，简称边 $(i,j,l)$。
- **每条边容量为 1**（"Each edge can carry at most one unit of flow"）→ 于是"$\mathrm{src}\to\mathrm{dst}$ 的最大流值 = 边不相交路径条数"。
- 再加**终点自环** $(\mathrm{dst}(d)_l,\mathrm{dst}(d)_{l+1})$，$l\in\{2,\dots,L_d\}$——允许流在**任意一层**到达终点后就地"坐电梯"到最后一层，从而实现"$\le L_d$ 跳"而不是"恰好 $L_d$ 跳"。

由于每条路径每走一步层号必 +1，**从 src 到 dst 的任何路径都自动满足 $\le L_d$ 跳**（论文 Fig. 2 的原话就是这个意思）。

### 4.2 Fig. 2 的玩具例子（值得一手算清）

- 场景：2 个地面站、2 个均匀分布的轨道面、共 6 颗卫星（$s_{11},s_{12},s_{13},s_{21},s_{22},s_{23}$），每星 3 条 ISL（$N_{ISL}=3$），每个地面站此刻有 2 颗可见接入星。
- 要求：$(src,dst)$ 至少 2 条边不相交路径（$r_{src,dst}=2$），路径长度不超 5 跳（$L_{src,dst}=5$）。
- 变换结果（Fig. 2b）：$src$ 只出现在第 1 层；第 2–5 层的「$V^d_l = V-\{src\}$」意味着**除 src 外每个节点在 2~5 层各有一份副本**；原图每条边在不同层间连一条有向边；$dst$ 在各层之间连自环。
- 5 层 + 自环 → 任意 src→dst 的流路径天然 $\le 5$ 跳。

### 4.3 时延约束版 SPLD 的约束

同一个目标 $\min\sum_i x(i)$，约束换成：

$$\sum_{\forall j:(j,i,l-1)\in E^d_t}\omega^{(l-1)d}_{ji}-\sum_{\forall j:(i,j,l)\in E^d_t}\omega^{ld}_{ij}=\begin{cases}-r_d,& i=\mathrm{src}(d)\\ r_d,& i=\mathrm{dst}(d)\\ 0,&\text{otherwise}\end{cases}\tag{9}$$

$$\omega^{ld}_{ij}+\omega^{(l+1)d}_{ji}\le 1,\quad \forall (i,j)\in E^t,\ d\in D,\ t\in T \tag{10}$$

$$\sum_{l\in\{2,\dots,L_d\}}\omega^{ld}_{ij}\le x(i),\quad \forall (i,j)\in E^t,\ d\in D,\ i\in S,\ t\in T \tag{11}$$

$$\mathrm{size}(d)\le \sum_{\forall j\in V^d}\omega^{L_d d}_{j,\mathrm{dst}(d)}\cdot \mathrm{Cap}^d_t\!\left(j,\mathrm{dst}(d)\right),\qquad
\mathrm{size}(d)\le \sum_{\forall j\in V^d}\omega^{1d}_{\mathrm{src}(d),j}\cdot \mathrm{Cap}^d_t\!\left(\mathrm{src}(d),j\right)\tag{12}$$

| 约束 | 含义 | 要点 |
|---|---|---|
| (9) | 分层图上每个节点的**流守恒** | "$\mathrm{src}$ 净流出 $r_d$、$\mathrm{dst}$ 净流入 $r_d$"——**一次性把"$r_d$ 条边不相交路径"编码成了 $r_d$ 个单位的单商品流**，这是全文最漂亮的一处建模 |
| (10) | $\omega^{ld}_{ij}+\omega^{(l+1)d}_{ji}\le1$ | 禁止在相邻两层上反向重复使用同一条物理链路——**消局部环** |
| (11) | $\sum_l \omega^{ld}_{ij}\le x(i)$ | 双重职责：① 卫星 $i$ 未被选入则其相关边不承载流量；② **保证路径边不相交** |
| (12) | 逐需求的链路容量 | 分流入口/出口处的容量条件 |

**关于 (11) 为什么是"边不相交"的关键**：分层图里"每条边容量 1"只保证**同一层内**同一条物理边不被两条路径同时占用；但两条路径完全可以在**不同层**（即不同跳数位置）上复用同一条物理边 $(i,j)$。约束 (11) 把这条物理边在**所有层上的使用次数之和**压到 $\le 1$（对入端卫星 $i$ 而言），才真正强制了**物理链路的边不相交**。这一条如果不写，整个"$r$ 条冗余路径"的语义就漏了。

### 4.4 式 (9) 的排版疑点

原文 (9) 的第二支写作 "$r_d$, if $i=\mathrm{dst}(d)_l$"，字面读是"**每一层的** dst 副本都净吸收 $r_d$ 单位流量"——这显然不可能满足（同一份流不可能被吸收 $L_d$ 次）。按上下文与分层图的常规构造，此处应是 $i=\mathrm{dst}(d)_{L_d+1}$（只有**最后一层**的 dst 是汇点），中间各层的 dst 靠自环把流送到最后一层、自身净流量为 0。属**排版/下标笔误**，不影响整体构造的正确性。

## 5. 复杂度：为什么必须走启发式（§III-C 末）

- 基础版与带时延版 SPLD 的**整数规划解空间都无法穷举**。
- 即使把所有 $r$ 设为 1、只取**单个时隙**，问题就退化为经典的 **Steiner Tree Problem**——已知 **NP-hard**。
- 作者的预实验结论：**规模到数百颗星就解不动了**。

所以"解 SPLD"这条路被否掉，必须另找出路。

## 6. MEGAREDUCE 机制（§IV）—— 全文核心

### 6.1 核心思想：把"求解"换成"判定 + 调参"

> while it is difficult to directly solve the SPLD problem and obtain the optimal solution, **it is doable to determine whether a given LSN is feasible** to meet survivability and performance requirements **in polynomial time**.

这是一个很通用的模式，值得单独记下来：**目标函数难优化，但可行性判定便宜时，就把优化问题改写成"外部搜索 × 内部判定"**。这里内部判定 = 分层图 + 逐需求最大流（线性/多项式），外部搜索 = 在星数上做二分式的 Shrink/Expand。

### 6.2 四步流程（Fig. 3）

1. **星座初始化**：从一个初始星座模式出发，可由运营商自行配置（例如他们**现有的**星座设计）。
2. **可行性检查**：调用 FeasibilityCheck，判断当前星座状态能否满足生存性与性能要求。
3. **星座调参**：可行 → 调 `Shrink` 稍微**减少**卫星；不可行 → 调 `Expand` 增加星座密度。
4. **解搜索**：反复迭代 2–3；在所有可行设计中输出**星数最少**的那一个。

注意流程里那个反馈量：$\Delta$ survivability / $\Delta$ delay / $\Delta$ capacity 的升降会决定 Tunning Action 的方向——但**具体实现里方向判定就是"可行/不可行"这一个二值信号**（见 Algorithm 1），三个 KPI 的 $\Delta$ 更像是框图上的概念示意。

### 6.3 搜索区间 $[N_{\min},N_{\max}]$（§IV-B）

- 星座除网络模型外还有**轨道特征**：主流互联网星座（Starlink、Kuiper）遵循经典 **Walker Delta**，用 $[Inc,O,M,H]$ 记法描述——$Inc$ 倾角、$O$ 轨道面数、$M$ 每面卫星数、$H$ 相邻面之间的相对间隔。**这些轨道信息用于缩小搜索范围。**
- $N_{\max}$ 初始 = 原始星座的卫星数（论文实现里就是 $|V|$，即卫星总数）。
- $N_{\min}$ 由 `GetSurvivableBound` 给出，依据一条**关键洞察**：
  > 要保证小区 $i$ 与 $j$ 之间有至少 $r_{ij}$ 条不相交路径，$i$ 和 $j$ 就**至少要有 $r_{ij}$ 颗可见卫星**。
  
  于是初始 $N_{\min}$ = "使每个小区 $i$ 在服务时段内、其传输范围内至少有 $\max_j\{r_{ij}\}$ 颗卫星"所需的最小卫星数。
  
  → 这是一个**很弱的必要下界**（"可见 $r$ 颗星"远不足以推出"存在 $r$ 条边不相交路径"），因此区间偏宽、二分次数偏多，且 $N_{\min}$ 本身可能仍高于真实最优。见 §9.2 第 5 条。

### 6.4 主循环：Algorithm 1

```
Input : LSN graph G={G_t}, demand set D, survivability R={r_ij}, delay L={L_ij}
Output: A simplified LSN based on {x_i}
 1: N_min ← GetSurvivableBound(G, {r_ij}, D)
 2: N_max ← |V|,  I ← 0                      # 迭代计数器
 3: G_result_list ← ∅,  [O,M,H] ← GetConsInfo(G)
 4: while I ≤ I_limit do
 5:     feasible ← FeasibilityCheck(G, D, R, L)     # Algorithm 2
 6:     if feasible == True:
 7:         N_max ← G.O · G.M
 8:         G_result_list.append(G)
 9:         G ← Shrink(G, N_min);  I ← I+1
10:     else:
11:         N_min ← G.O · G.M
12:         G ← Expand(G, N_max);  I ← I+1
13: return G ← argmin_{∀G ∈ G_result_list} ( |G.O · G.M| )
```

读法：**可行就把上界压到当前规模并继续缩；不可行就把下界抬到当前规模并扩。** 每轮把当前星数 $G.O\cdot G.M$ 写进对应的界，等价于一次二分。最后从所有可行过（被 append 进列表）的构型里取星数最小的那个——**注意是取历史最优，不是取最后那个**，这点很重要：Shrink 一旦缩过头变得不可行，最后停留的构型可能是不可行的，必须回落到列表里的最优可行解。

### 6.5 可行性检查：Algorithm 2

```
Input : G={G_t}, D, R={r_ij}, L={L_ij}
Output: Feasibility decision F
 1: F ← True
 2: for each t in T do                          # 逐时隙
 3:     for each j in C do                      # 初始化容量
 4:         AvaiCap_up[j]   ← Σ_{i∈S} e^t_ji · Cap^t_ji
 5:         AvaiCap_down[j] ← Σ_{i∈S} e^t_ij · Cap^t_ij
 6:     for each d in D do
 7:         G^d_t ← GraphTransform(d, G_t)      # §III-C 分层图
 8:         r ← CalculateMaxFlow(src(d), dst(d), G^d_t)
 9:         if r < r_{src(d),dst(d)}: return F ← False      # 生存性
10:         s ← size(d)
11:         if s ≤ AvaiCap_up[src(d)] and s ≤ AvaiCap_down[dst(d)]:
12:             AvaiCap_up[src(d)]   ← AvaiCap_up[src(d)]   − s
13:             AvaiCap_down[dst(d)] ← AvaiCap_down[dst(d)] − s
14:         else: return F ← False                          # 容量
15: return F
```

三个要点：

1. **生存性判定 = 分层图上求一次最大流**，与 $r$ 比较。因为分层图每条边容量 1，"最大流值 ≥ $r$" 就等价于"存在 $r$ 条**跳数受限且边不相交**的路径"——判定是多项式的。
2. **时延要求的实际口径**：代码里取 $L_{\mathrm{src}(d),\mathrm{dst}(d)}=\lambda\cdot L^{SP}_{\mathrm{src}(d),\mathrm{dst}(d)}$，$L^{SP}$ 是最短路——所以 $\lambda$ 是"相对最短路的跳数膨胀系数"。
3. **容量判定是"逐需求顺序扣减"**：$AvaiCap$ 是跨需求累减的，先到先得。这意味着**可行性结论依赖需求的遍历顺序**，而论文未说明顺序、也没做顺序敏感性实验。→ 见 §9.2 第 4 条。

**还要注意**：整个 Algorithm 2 **没有出现 ISL 容量**——与 §III-A 的假设一致（激光 ISL 容量远高于 GSL、不会成瓶颈）。这是本文最强的简化，也是最容易被攻击的地方。

### 6.6 Constellation Tuning：Algorithm 3

Expand / Shrink 都只用**二分**的思路在 $[N_{\min},N_{\max}]$ 里挪：

```
Expand(G, N_max):
 1: currentN ← G.O · G.M
 2: targetN  ← ⌊(currentN + N_max) / 2⌋
 3: if G.O ≤ G.M:  加 ⌊(targetN − currentN) / G.M⌋ 个轨道面
 4: else:          每面加 ⌊(targetN − currentN) / G.O⌋ 颗卫星

Shrink(G, N_min):
 5: currentN ← G.O · G.M
 6: targetN  ← ⌊(currentN − N_min) / 2⌋        ← 见下方疑点
 7: if G.O ≤ G.M:  每面减 ⌊(currentN − targetN) / G.O⌋ 颗卫星
 8: else:          减 ⌊(currentN − targetN) / G.M⌋ 个轨道面
```

**核心原理（一句话）**：往 $O=M$ 靠。

论文给的理由是 Walker Delta 的一条性质——**任意两颗通信卫星之间最短路径的最大跳数（跳数直径）为 $\lceil(O+M)/2\rceil$**。给定总星数 $N=O\cdot M$，由 AM-GM：
$$O+M \ge 2\sqrt{OM}=2\sqrt{N},\quad \text{等号当且仅当 } O=M$$
所以 $O=M=\sqrt N$ 时跳数直径最小。而 $N_{\min}$ 已经兜住了生存性下界，于是**把 $O,M$ 拉近就等于在不牺牲生存性的前提下压低时延上界**。

而且 Algorithm 3 的分支逻辑与这条原理是**自洽**的：
- Expand 时若 $O\le M$ → 加轨道面（$O$ 上去追 $M$）；否则加每面星数（$M$ 上去追 $O$）。
- Shrink 时若 $O\le M$ → 减每面星数（$M$ 下来靠 $O$）；否则减轨道面（$O$ 下来靠 $M$）。

### 6.7 一处可疑的写法

Shrink 的 `targetN ← ⌊(currentN − N_min)/2⌋` 与 Expand 的 `targetN ← ⌊(currentN + N_max)/2⌋` **不对称**——按二分的中点语义，Shrink 应为 $\lfloor(currentN+N_{\min})/2\rfloor$（"$+$"印成"$-$"）。按字面 $(currentN-N_{\min})/2$ 会**一步缩到远低于 $N_{\min}$** 的位置（例：$currentN=4408,N_{\min}=1000\Rightarrow targetN=1704$），属于激进过冲。

不过这一点**不影响算法能跑通**：缩过头 → 下一轮判定不可行 → Expand 把规模拉回区间，只是迭代次数变大。结合 GitHub 仓库里"迭代次数不超过 10"的默认设置，可以推测试验中确实依赖这种"过冲—回拉"。这与 §9.2 第 6 条（结果依赖 $I_{limit}$ 与起点）是一条链上的问题。

### 7.2 三类需求下的星数（Fig. 4 / 5 / 6）

| 图 | 横轴（需求） | 观察 |
|---|---|---|

| **Fig. 6** | 时延约束 $\lambda\in\{1.35,1.5,2,2.5,3\}$ | $\lambda$ 越小 → 需要**更密**的星座，因为要在更紧的跳数上限内凑出足够条数的冗余路径 |

**这三个图的正确读法**：它们是"MEGAREDUCE 能把『需求 → 星数』这条曲线画出来"，而**不是**"能省 20% 星"。20% 只是 $r_{\min}=6$ 那个点的副产品；论文真正的价值是这条**单调、可扫的 trade-off 曲线**。

### 7.3 轨道参数的影响（Fig. 7）

Fig. 7 是三维曲面：**所需星数 vs 卫星高度 vs 轨道倾角**，分别在 $r_{\min}=2$ 与 $r_{\min}=4$ 下给出。两条观察：

1. **高度越高，所需星数越少**。原因：覆盖范围更大 → 单个小区能被更多卫星服务 → 冗余链路更多。**但代价是星地传播时延变大**（论文自己点出了这个 trade-off）。
2. **倾角越大，所需星数越多**。论文的解释：多数通信小区位于 $[-70^\circ,70^\circ]$ 纬度带内，倾角更大的星座覆盖这一带时能给出更高的卫星密度，从而为"热小区"提供更好的生存性与性能。

> 说明：第 2 条的机制论述偏**定性**，没有给解析推导或分量拆解。直觉上"倾角增大 → 卫星在 ±70° 带内的时间份额下降 → 维持同等冗余度需更多星"与观察方向一致，但作者给的理由方向相反（说"能提供更高密度"），读的时候建议只记**经验趋势**（倾角↑ → 星数↑），别把解释当结论。

### 7.4 抗毁性分析（Fig. 8，§V-D）

两种失效模型：
- **太阳风暴失效模型**：一批**邻近**卫星同时被摧毁（典型事件：2022-02-04 的 49 颗 Starlink 卫星失效 [1]）。
- **随机失效模型**：卫星以一定概率失效（硬件故障 / 星上器件老化）。

假设：高层路由协议能高效检测冗余路径、在当前路径失效时切到备份路径。
指标：**可达率 reachability** = 仍互相可达的通信对数 / 通信对总数。

对照对象：**ultra-dense LSN design** [12]（Deng 等，TWC 2021）。

结论：随着被毁卫星数与失效率上升，可达率普遍下降（存活有效路径不够了）；但**在相同星座规模下（680 / 830 / 940 颗），MEGAREDUCE 的可达率始终高于 UltraDense**——因为它是在**生存性 + 性能约束下联合优化**出来的设计，抗失效能力天然更强。

> 一点公允性提示：UltraDense 的保证是"每个用户终端的回传需求"，不是 $r$-边连通，两者优化目标不同。"同规模下 MEGAREDUCE 更抗毁"这个结论成立，但不宜读成"MEGAREDUCE 全面优于 UltraDense"。

## 8. Case Study（§V-E）—— 工程价值最高的一段

### 8.1 一个被忽视但很漂亮的观察：这个映射是可逆的

MEGAREDUCE 本质上是一个函数
$$N^{sat}_{\min} \leftarrow F(req)$$
其中 $req$ 是各类需求（$r_{\min}$、容量、$\lambda$ 等）。既然 $F$ 可算，就能反过来算
$$req \leftarrow F^{-1}(N^{sat})$$
即"**给定星数上限，我能达到的最好需求水平是多少**"。论文给的例子：若已知 $r_{\min}=5/6$ 分别至少需要 1500/1600 颗星，那么**给定 1550 颗星，可以构建存活要求 $r_{\min}$ 最高到 5 的 LSN**。

把 $F$ 从"设计工具"变成"**决策查询接口**"，这是本文明面上不显眼、但最可迁移的一步。

### 8.2 分期部署（Incremental Deployment）

mega-constellation 必须**分批发射**、往往耗时数年才部署完。问题：在只有少量在轨卫星的早期阶段，星座本身的抗毁能力很差，能不能通过"改摆法"改善？

做法：取真实 Starlink 从 **2019-12 到 2023-06** 的历史数据（来自 SpaceTrack [52]），观察其 $r_{\min}$ 在 3.5 年内从 **0 涨到 5**。然后设想一个"平行世界"：**每次发射的卫星数与真实 Starlink 完全相同，但按 MEGAREDUCE 的方案来构造星座**。

结果（Fig. 9a）：相同星数下，MEGAREDUCE 指导的星座**在部署早期就能达到更高的生存性**。→ 结论：星座设计不是上线后才考虑的事，**第一批卫星怎么摆就决定了早期的抗毁下限**。

### 8.3 在轨星座调整（In-orbit Constellation Adjustment）

mega-constellation 用的是寿命较短的小卫星，**即使全部部署完成，也会有卫星随时间陆续失效**。

数据：从 SpaceTrack 近 3 年历史数据发现 Starlink 的**年衰减率 AAR ≈ 2.6%**（每年约 2.6% 的卫星变为 inactive）。Fig. 9b 给出了 AAR = 3% / 5% 两种情形下未来 3 年的规模预测：**若不补发新星，生存性会逐渐下滑**；若按 MEGAREDUCE 的解**及时调整星座结构**，则在规模下滑过程中仍能维持较高的生存性。

## 9. 我的评价

### 9.1 能用的（三条）

1. **"需求 → 星数"的可查询映射（$F$ 与 $F^{-1}$）**——这是最直接的可用产出。任何"给我 $r$ 条备份路径 / 每小区 $X$ Mbps / 时延不超过 $\lambda$ 倍最短路，最少要多少颗星"的问题，都可以直接调它。分期部署与在轨衰减两个 case study 已经示范了怎么用。
2. **分层图 + 单位容量 + 逐需求最大流**这套判定范式——把"$k$ 条**跳数受限且边不相交**的路径"转成一次多项式时间的 max-flow。这个技巧**与卫星无关**，可以原样搬到任何"带跳数上限的链路不相交路由"问题上。
3. **"优化难 / 判定易"的解题模式 + 一个开源实现**——仓库 `SpaceNetLab/MegaReduce` 真的能跑（见 §11），且 `con_expand` / `con_shrink` / 故障模型都是显式可替换的接口。

### 9.2 不能用的 / 可攻击的点（做研究重点看这段）

1. **解空间极窄**：MEGAREDUCE 只在 $(O,M)$ 两个维度上搜，且**只搜均匀的 Walker-Delta 同族构型**——不改相位 $f$、不改高度/倾角（它们只是 Fig. 7 的**输入**维度，不是优化变量）、不做非均匀星座、不跨壳层联合优化。这从根本上解释了为什么收益只有 20% 而不是数量级：**它回答的是"同一族构型里取哪个规模"，不是"该用哪种构型"**。
2. **ISL 容量被假设掉**：容量检查只算小区级 GSL 上/下行（Algorithm 2），ISL 容量一次都没出现，依据是"激光 ISL 容量远高于射频 GSL、不会成为瓶颈"。当 $r$ 很大、或者局部热点导致某几条 ISL 成为汇聚瓶颈时，这个假设会直接崩掉。**这是最容易补、也最有论文味的一个缺口。**
3. **只要求"存在" $r$ 条边不相交路径，不管怎么选、怎么恢复**：路由与切换被一句话推给"高层路由协议会快速检测并切到备份路径"（§V-D）。多径如何分配流量、切换抖动多大、备份路径能否同时承载——全部未建模。
4. **容量判定顺序敏感**：$AvaiCap$ 逐需求累减（先到先得），不同需求遍历顺序会给出不同可行性结论。论文未说明顺序、也未做敏感性实验。这是一个具体的**可复现性缺口**。
5. **$N_{\min}$ 的下界太弱**：`GetSurvivableBound` 只要求"每小区至少有 $\max_j r_{ij}$ 颗**可见**卫星"，而"可见 $r$ 颗"离"存在 $r$ 条边不相交路径"还很远。下界弱 → 搜索区间宽 → 迭代多，且 $N_{\min}$ 可能本身就高于真实最优。
6. **算法无近似比、无最优性界，且结果依赖起点与 $I_{limit}$**：只承诺"多项式时间内的可行解"。算法从"运营商**现有**星座"出发，起点不同 → 二分路径不同 → 收敛结果可能不同；仓库默认迭代上限 10 次。论文**没有做起点敏感性 / 迭代上限敏感性实验**。这是最实质的一条。
7. **时延约束用的是跳数，不是真时延**：$L_d=\lceil\lambda L^{sp}_{ij}\rceil$ 是**跳数比**。$L=\lambda$ 倍跳数 $\ne$ $\lambda$ 倍时延——LSN 里跨轨链路与同轨链路的物理长度差异很大（同轨相邻 ISL 长度恒定，跨轨链路长度随相对位置大幅变化），跳数和时延在 LSN 里相关性比地面网更弱。借用 Gvozdiev [41] 的地面网做法在这里是**可质疑的**。
8. **节点冗余缺失**：生存性用**边**不相交定义，只覆盖链路故障；卫星（节点）失效需要节点不相交路径。而论文的故障模型（太阳风暴一次毁掉一簇邻近卫星、随机失效率）恰恰是**节点**故障。**"用边连通性约束去对抗节点失效"存在语义错位**——作者用实验（Fig. 8）而非模型来兜这一点。
9. **约束 (2) 非线性** $x(i)x(j)\ge e^t_{ij}$，做 ILP 需线性化为 $e^t_{ij}\le x(i)$、$e^t_{ij}\le x(j)$，论文未提。属形式化严谨性瑕疵（对启发式算法无影响，因为它不解 ILP）。
10. **约束 (8) 是指数级割约束族**：对所有子集 $V'$ 施加约束，直接交给求解器不可行，需 cut separation。虽然推导正确（见 §3.2），但**论文没有说明这一项在实现中如何处理**——实际上 MEGAREDUCE 根本不碰它，只用逐需求 max-flow 做判定。所以**两个 ILP 是"问题声明"，不是"被求解的对象"**，读的时候别误以为 20% 是 ILP 解出来的。
11. **"polynomial time" 的说法需要限定**：单次可行性检查确实是多项式时间，但整体搜索是 $O(I_{limit}\times |T|\times |D|\times \text{MaxFlow})$，其中 $|T|$ 随时隙粒度（要跑"完整回归周期"）线性增长，实际运行时间不便宜。论文**没给任何运行时间数据**（只有迭代次数上限），这是评测上的明显空缺。
12. **评测覆盖偏窄**：仅 Starlink 一期与 Kuiper 两个构型；未评 OneWeb / Telesat；未给不同 $N_{ISL}$ 的消融（固定 4）；未给时隙粒度的影响。

## 10. 与本项目方向的接口（TE / SRv6 / Mininet / RL）

### 10.1 最直接的一条：把 Shrink/Expand 换成 RL

MEGAREDUCE 的外部搜索层就是**"离散设计空间上的黑箱搜索 + 代价昂贵的可行性判定"**：

- **状态**：当前 $(O, M, Inc, \text{altitude})$，以及当前判定结果的三项裕量（$\Delta$survivability / $\Delta$delay / $\Delta$capacity）；
- **动作**：加/减轨道面、加/减每面星数（论文里的 4 种）；
- **奖励**：星数下降量 − 判定开销惩罚（判定次数可直接量化成算力成本）；
- **难点/卖点**：论文用的是**结构固定的二分**（且 Shrink 那一步过冲），完全没用上裕量信息。用 RL 学一个策略，目标就是**在更少次数的可行性判定内找到同样好甚至更好的解**——这是一个**评价指标干净（判定次数 = 样本效率）**、baseline 明确（Algorithm 1 + Algorithm 3）、且与已有的 T3Planner（rule-aided RL + 规则求解器协同）同构的题。**我认为这是本文留给你们组最现成的一个洞。**

### 10.2 TE / SRv6 视角

- **分层图 max-flow 找出的 $r$ 条边不相交路径，就是天然的 SRv6 备份段列表**：主路径走最短跳数路径，$r-1$ 条备份路径直接用 uSID 段列表显式编码（论文只要求"存在"，不指定如何用；SRv6 恰好提供了"显式指定"的手段）。**"SPLD 定规模 + SRv6 段列表定多径"是把两层接起来的一条完整链。**
- **跨需求顺序敏感**（§9.2 第 4 条）本质是一个**流量工程问题**：需求的准入顺序 + 每条需求选哪条路径。把 Algorithm 2 里的顺序固定策略换成一个 TE 求解器（或一个 RL 调度器），就是一个干净的增量贡献。

### 10.3 与其他工作的组合位置

```
需求 (r_min, 每小区容量, λ)
      │
      ▼
  SPLD / MEGAREDUCE   ← 本文：定「多少颗星、怎么摆」
      │
      ▼
  LAMP / DTLS         ← 定「剩余激光终端怎么用、临时链路怎么切」
      │
      ▼
  OPSPF / SRv6 段列表 ← 定「包怎么走、故障怎么切」
```
三层串起来就是一条完整的"卫星网络设计 → 拓扑调度 → 路由"链路，非常适合作为一个**系统型论文的骨架**，而这三篇恰好都在你工作区里。

### 10.4 Mininet 复现的低成本路径

不建议复现全文（需要 Gurobi + 完整星座仿真）。**建议只切下"分层图 + max-flow 判定"这一块**做最小实验：用简化 Walker-Delta 的解析位置或 SkyField 生成坐标 → 按最小仰角/距离阈值建可见性图 → 把 $\le L$ 跳的边不相交路径问题建成有向分层图（OSPF 式逐层复制节点）→ 用 `networkx.maximum_flow` 求最大流 → 扫 $\lambda$ 与 $r$，看"星数 vs 需求"曲线的形状是否与 Fig. 4/6 同构。**核心要验证的两个 claim：① 曲线单调；② $\lambda$ 越小星数越陡增。**

### 11.2 自研最小可跑版本（不依赖 Gurobi）

1. **算位置**：用 `skyfield` + TLE，或用 Walker-Delta 解析式（圆轨道假设足够）生成一个回归周期内的卫星位置序列。
2. **建可见性 / 建图**：同轨相邻 + 邻轨 ISL，按最小距离或仰角阈值筛出 $I^t_{ij}$；每星同时启用的 ISL 数 $\le N_{ISL}$。
3. **分层图变换**：对给定 $(src,dst)$ 与 $L_d$，复制节点到 $L_d+1$ 层，相邻层之间按 $E^t$ 连有向边、容量 1，dst 加跨层自环——**照 §4.1 抄，注意别忘了约束 (11) 对应的"物理边跨层去重"**（这是最容易漏、漏了语义就错的地方）。
4. **判定**：`networkx.algorithms.flow.maximum_flow` 求 src→dst 最大流，与 $r$ 比。
5. **调参壳**：在 $(O,M)$ 上做二分（先按论文 Algorithm 3 实现一遍，作为 RL 的 baseline）。
6. **要复现的两个 claim**：曲线单调性、$\lambda$ 敏感性。

## 12. 一句话复述（如果只记三句）

1. **问题**：卫星网络设计里最该被回答却没人答清的是"**到底要多少颗星**"；本文把它写成 SPLD——最小星数 s.t. 每对小区在所有时隙都有 $r_{ij}$ 条**跳数受限的边不相交路径** + 上/下行容量约束。NP-hard（退化为 Steiner Tree）。
2. **方法**：不硬解。**时延约束 → 有向分层图 → 一次最大流**得到多项式时间的可行性判定；外面套 **Shrink/Expand 二分**，并且往 $O=M$ 靠（因为 Walker Delta 的跳数直径是 $\lceil(O+M)/2\rceil$，$O=M$ 时最小）。这是 MEGAREDUCE。
3. **结果与价值**：$r_{\min}=6$ 时仍能在 Starlink 上减 20.05%、Kuiper 上减 21.88%；但真正的产出是"**需求 ⇄ 星数**"的可逆映射 $F/F^{-1}$，可直接用于分期部署与在轨衰减下的结构调整。**最现成的研究缺口 = 用 RL 替掉那个结构固定的二分。**
