# 自己的理解



#### **题目：** 

​	Your Mega-Constellations Can Be Slim:  A Cost-Effective Approach for Constructing Survivable and Performant LEO Satellite Networks

​	你的巨型星座可以更精简：一种面向可生存和高性能 LEO 卫星网络的低成本构建方法

#### **出处：**

​	IEEE INFOCOM 2024

#### **组织：** 

​	清华大学网络科学与网络空间研究所，中关村实验室

#### **研究背景：**

​	大规模部署 LEO 卫星虽然能提升卫星网络的网络生存性与性能，却也会带来更高的部署成本、卫星交汇风险、空间碎片。

#### **研究内容：**

​	从网络的角度看，构建一个可生存且性能达标的 LSN，究竟需要多少颗的卫星？

#### **发展现状：**

SpaceX、亚马逊等领先玩家计划以**极其庞大**的 LEO 卫星数量部署其巨型星座。例如，SpaceX 的 Starlink 与亚马逊的 Kuiper 项目一期将分别包含约 **4,408** 颗与 **3,236** 颗 LEO 卫星；此外，SpaceX 还期望在下一部署阶段把 Starlink 的星座规模扩展到 **42,000** 颗。在 LSN 中部署更多卫星带来的主要网络收益包括：【好处】

- **更好的生存性。** LSN 中的节点与链路不可避免地会因太阳风暴、辐射干扰与硬件故障等一系列复杂因素而失效。在 LSN 中部署更多卫星可以提供更多冗余的备份链路与路径，从而有效提升网络的生存性。
- **更好的性能。** LSN 旨在为全球地面客户提供宽带网络服务。部署更多具备多波束高吞吐点波束的 LEO 卫星，可以带来更广的服务覆盖以及更高的星座级网络容量。

#### **现状应对的挑战：**

尽管有上述网络收益，近期也有一些声音指出，巨型星座的高密度会带来额外的可持续性问题，例如：【劣势】

- **更高的成本。** 无疑，LSN 中卫星越多，卫星部署与维护的成本就越高。因此，除 SpaceX、亚马逊这类资金雄厚的巨头之外，另一些组织正在探索以**远少得多的卫星数**来明智设计星座的可行路径（例如 IRIS² 与 Sfera 星座）。
- **治理问题（如空间交会与碎片）。** 随着星座密度上升，航天器交会事件可能更频繁。更多卫星还会导致空间碎片累积增加，这对航天机构与卫星运营商而言是重大关切，因为它对在轨运行的 LSN 构成巨大风险 。

#### **研究现状：**

- 一些工作专注于设计卫星网络（星座）以优化通信覆盖、时延、网络容量；然而这些 LSN 设计方法<u>并未考虑在空间中各种潜在失效因素下保证网络生存性</u>。
- 一些工作系统的研究了传统静态地面电信网络中的可生存网络设计问题，但是<u>很难把他们直接应用到整条网络骨干高度动态的新型 LSN 上</u>。
- 一些工作提出了多层空间网络设计，引入地球同步卫星 GEO 来转发 LEO 之间的流量、从而减少所需卫星数。然而，由于轨道高度更高，<u>引入 GEO 会导致增加网络时延</u> ，并且 <u>GEO 卫星的服务容量通常有限</u>，难以支撑数量庞大的宽带用户。

#### **文中做出的工作：**

1. 形式化了可生存且高效的 LSN 设计问题（survivable and performant LSN design, SPLD），目标是同时满足多项生存性（网络在各类故障发生时维持可接受服务水平的能力）和性能要求（任意地面通信对之间足够数量的冗余路径、必要的链路容量、可接受的端到端时延）的前提下，找到 LSN 所需要的最少卫星数；
2. 为解决这 SPLD 问题，文中提出了 MEGAREDUCE —— 一种需求驱动的 LSN 优化机制，它能在多项式时间内设计出满足生存性与性能要求的 LSN；
3. 依据真实的星座信息与卫星轨迹驱动的大量评估，验证了 MEGAREDUCE 在按需构建可生存、高性能 LSN 上的成本有效性。

#### LSN 的设计需求：

1. 网络生存性：各类故障发生时维持可接受服务水平的能力
2. 低时延
3. 高容量
4. 合适的规模：影响 LSN 成本的核心要素（经济成本、轨道资源、无线电频谱资源）

#### 系统建模：

- 星座网络模型

  - $S = \{s_1,s_2,...s_n\}$ 表示 卫星集合

  - $C = \{c_1,c_2,...,c_n\}$ 表示 小区集合
  - 二值量 $I_{ij}^t$ 表示 $ 节点~i~和节点~j~在时隙~t~是否互相可见 $
  - 二值量 $ e_{ij}^t $ 表示在 $时隙~t~节点~i~与~j~之间存在活跃通信链路$
  - 时变图 $G^t = (V,E^t)$，顶点集 $V = S\cup C$ ，边集 $E^t$ 包含时隙内所有活跃的多对多 GSL 与 ISL

- 容量模型

  - 一个点波束服务一个地面小区
  - 时隙 $t$ 内，**卫星 $i$ 与小区 $j$ 之间** 该点波束的上行/下行容量分别记为 $\mathrm{Cap}^t_{ji}$ 与 $\mathrm{Cap}^t_{ij}$（$i\in S,\ j\in C$）
  - $\mathrm{Cap}^{\max}_{up}$（$\mathrm{Cap}^{\max}_{down}$）为一颗卫星的最大上行（下行）容量
  - **某颗卫星 $i$ 的实时上行容量 **可计算为 $\sum_{j\in C}e^t_{ji}\cdot \mathrm{Cap}^t_{ji}$
  - **某颗卫星 $i$ 的实时下行容量 **可计算为$\sum_{j\in C}e^t_{ij}\cdot \mathrm{Cap}^t_{ij}$
  - **某个小区** $j$ 在时隙 $t$ 的 **总可达上行容量** 可计算为 $\sum_{i\in S}e^t_{ji}\cdot \mathrm{Cap}^t_{ji}$
  - **某个小区** $j$ 在时隙 $t$ 的 **总可达下行容量 **可计算为 $\sum_{i\in S}e^t_{ij}\cdot \mathrm{Cap}^t_{ij}$

- 通信需求

  - $D = \{d_1,d_2,...,d_n\}$为通信需求集合，每一个需求 $d_k\in D$ 关联一个三元组 $(\mathrm{src}(d_k),\mathrm{dst}(d_k),\mathrm{size}(d_k))$
  - 其中 $\mathrm{src}(d_k),\mathrm{dst}(d_k)\in C$ 是 $d_k$ 的两端（即源小区与目的小区）
  - $\mathrm{size}(d_k)$ 是该需求的流量（例如数据速率）

- 生存性要求

  - 对任意一条关联两个不同节点 $\mathrm{src}(d)=i$、$\mathrm{dst}(d)=j$ 的需求 $d$，一条 $[i\to j]$ **路径 **表示 LSN 图中的一个节点与边的序列，对需求 $d$ 可能存在多条可用路径
  - 若 **没有任何一条边出现在多于一条路径中 **，我们称这组 $[i\to j]$ 路径为 **边不相交（edge-disjoint）路径**
  - 若 在所有时隙 中 $i$ 与 $j$ 之间都至少有 $R$ 条边不相交路径，则称关联 $i,j$ 的需求 $d$ 是 **$R$-边连通** 的
  -  $r_{ij}$ 为关联通信对 $(i,j)$ 的需求 $d$ 的 **生存性要求**，其中 $i$、$j$ 是两个不同的地面小区（$i,j\in C$），意味着在所有时隙中都要求 $i$ 与 $j$ 之间至少有 $r_{ij}$ 条边不相交路径，$r_{ij}$ 越高表示冗余路径越多，$i$ 与 $j$ 之间的通信会话就能抵抗更多链路失效

#### 基础 SPLD 问题：

**定义：** 给定一个基于巨型星座的原始 LSN，以及一系列生存性和性能要求，如何优化网络结构，找到一个满足全部要求且卫星数最少的子图？【找子图】

**表示：**

- 二值量 $x(i)$ 表示卫星 $i\in S$ 是否被包含在该子图中
- $T$ 表示所有时隙的集合
- **目标函数：** $\min\sum_{i\in S}x(i)$
- **约束函数：**
  1. 两通信端只有在互相可见、可连接的时候才能建立链路
  2. 卫星只有被包含在子图中，才能建立通信链路
  3. 被激活的 ISL 总数不能超过可用发射机数量（$N_{ISL}$）
  4. 上行业务需求不超过小区上行总可达容量
  5. 下行业务需求不超过小区下行总可达容量
  6. 小区上行总可达容量不超过卫星最大上行容量
  7. 小区下行总可达容量不超过卫星最大下行容量
  8. 生存性要求（ $p$ 与 $q$ 之间存在至少 $r_{pq}$ 条边不相交路径 ）

#### 带时延约束的 SPLD 扩展：

**描述：**

​	基础 SPLD 形式化保证了关联 $i,j$ 的通信需求具有 $r_{ij}$-边连通性，但是同时还需要满足一定的时延要求，即这 $r_{ij}$ 条边不相交路径的长度不应超过某一阈值，以<u>保证可接受的端到端时延</u>（满足时延约束 / 长度约束）。

- 图变换

  - 把原本的无向图 $G^t$ 转换为一个 **有向分层图**
  - 把基础 SPLD 问题分解为 $|D|$ 个子问题，每条需求对应一个
  - 假设关联 $i$ 与 $j$ 的需求 $d$ 的路径长度应低于 $L_d$（也记作 $L_{ij}$），$L_d$ 的取值可设为 $\lceil\lambda\cdot L^{sp}_{ij}\rceil$，其中 $L^{sp}_{ij}$ 是 $i$ 与 $j$ 之间的最短路径长度，$\lambda\ge1$ 是约束因子
  - 用一个由 $L_d+1$ 层构成的有向图来对每个关联需求 $d$ 的子问题建模
  - 每条 $d$ 构造一个有向分层图 $G^d_t=(V^d,E^d_t)$，其中 $V^d=V^d_1\cup V^d_2\cup\dots\cup V^d_{L_d+1}$，又有 $V^d_1=\{\mathrm{src}(d)\}$、$V^d_{L_d+1}=\{\mathrm{dst}(d)\}$，并对 $l=2,\dots,L_d$ 定义 $V^d_l=V-\{\mathrm{src}(d)\}$
  - $v^d_l$ 为 $v\in V$ 在图 $G^d_t$ 第 $l$ 层中的副本
  -  $G^d_t$ 的边集定义为：$E^d_t=\{(i^d_l,j^d_{l+1})\mid(i,j)\in E^t,\ i^d_l\in V^d_l,\ j^d_{l+1}\in V^d_{l+1},\ l\in\{1,\dots,L_d\}\}\ \cup\ \{(dst(d)_l,dst(d)_{l+1})\mid l\in\{2,\dots,L_d\}\}$
  - 把 $i^d\in V^d_l$ 与 $j^d_{l+1}\in V^d_{l+1}$ 之间的有向边记为 $(i,j,l)$
  - 记 $\mathrm{Cap}^d_t(i,j)$ 为边 $(i,j)$ 在图 $G^d_t$ 中的链路容量

#### 问题解决（需求驱动的 LSN 优化）

**MEGAREDUCE 概览：**

​	虽然直接求解 SPLD 问题、获得最优解很困难，但<u>判定一个给定 LSN 是否可行地满足生存性与性能要求，是可以在多项式时间内完成的</u>。具体地，MEGAREDUCE <u>从一个初始星座状态出发，在多轮迭代中反复调整星座结构与卫星数量，并搜索出卫星数最少的可行 LSN 设计</u>。

**MEGAREDUCE 搜索满足各项要求的 近最优 LSN 设计的步骤：**

1. 星座初始化：从一个初始星座构型出发
2. 可行性检查：基于初始星座，检验星座的当前状态是否满足生存性和性能要求
3. 调参：基于可行性检查结果，若当前星座是可行的（即能满足生存性与性能要求），使用 **Shrink** 方法略微减少卫星数量；否则，调用 **Expand** 函数以提升星座密度
4. 解搜索：迭代重复可行性检查与星座调参过程，在所有可行的 LSN 设计中，MEGAREDUCE 输出卫星数最少的那一个【1】

**【1】搜索 LSN 设计方案：**

1. 基于轨道特征（记法 $[Inc,O,M,H]$，其中 $Inc$ 是轨道倾角，$O$ 是等间隔轨道面的数量，$M$ 是每个轨道面内的卫星总数，$H$ 是卫星与相邻轨道面之间的相对间隔）计算所需卫星数的搜索区间，续 2
2. 在一个记为 $[N_{\min},N_{\max}]$ 的区间内搜索所需的最少卫星数，$N_{\max}$ 被设为原始星座中的卫星数量，初始 $N_{\min}$ 被计算为"能够保证每个小区 $i$ 在服务时段内、其传输范围内至少有 $\max\{r_{ij}\}\ (\forall j\in C)$ 颗卫星"所需的最少卫星数
