## SPLD / MEGAREDUCE（INFOCOM 2024）时延约束可行性判定 —— 松弛性核查

用户的质疑：论文是否其实没做时延可行性判定，而是转成有向分层图后「默认满足」。

核查结论（已核对原文 §III-C、Algorithm 2、§VI 讨论）：

1. **时延是被检查的，只是构造式**。分层图边只能 l→l+1，加上 dst 自环填充，
   任何 src^1 → dst^(L+1) 的流路径天然 ≤ L_d 跳。属于 hop-constrained path 的标准技巧。
   原文原话：By this transformation, we guarantee that any path from src to dst
   satisfies the L-hop constraint (L=5). Algorithm 2 确实没有单独的 delay 判定行。

2. **真正的漏洞在抗毁侧**：分层图里同一条物理边 (i,j) 在每层都是独立的弧 (i,j,l)，
   单位容量 max-flow 只保证「分层弧不相交」，不保证「物理链路不相交」。
   跨层复用同一物理边会被算成多条不相交路径 → 可行性判定是原问题的**松弛**，会过判。

3. **反例（已用代码验证）**：原图边 {s-a, s-x, x-a, a-b, b-t}，L=4，r=2：
   - 分层图 max-flow = 2（判可行）
   - 真实物理边不相交且 ≤4 跳：只有 1 条（s-a-b-t 用掉 a-b、b-t 后，第二条 s-x-a 卡死）
   验证脚本：`layered_graph_counterexample.py`（工作区根目录，可直接跑）。

4. **ILP 与算法不一致**：论文 ILP 的约束 (11)（Σ_l ω^{ld}_{ij} ≤ x(i)，x(i)∈{0,1}
   ⇒ 同一物理边在所有层最多用一次）本可堵住这个漏洞，但 Algorithm 2 的多项式时间
   判定器根本没实现它，只跑了 max-flow。即：ILP 精确（NP-hard），判定器是它的松弛。

5. **第二个薄弱点**：Algorithm 2 第 848–852 行把 L_d 设为 λ · L^SP，
   L^SP 取「当前 LSN 中的最短路」。Shrink 把星座变稀 → L^SP 自身变大 → 时延预算自动放宽，
   约束成了移动靶子；若每轮重算，时延约束几乎不 binding。

6. **第三个近似**：用跳数当传播时延的代理。LEO 中距离主导时延，同跳数路径长度差别很大。
   论文讨论部分只承认了 altitude↑ → 传播时延↑ 的权衡，没把真实传播时延写进约束。

影响：论文报告的 Starlink -20.05% / Kuiper -21.88% 严格说是「松弛下」的节省，偏乐观。
